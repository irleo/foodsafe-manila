Task 6: Fix prediction run generation and persistence after upload
Fix prediction run persistence so a successful official case upload creates a saved PredictionRun document.

Current issue:
- Raw XLSX upload works.
- Dataset is saved in the foodsafemanila database.
- OfficialCase records are saved in officialcases.
- But predictionruns collection is empty after upload.
- The system needs to save monthly district-based forecasts in MongoDB after official case import.

Requirements:
1. After a successful official case import, trigger the monthly district prediction refresh.

2. The prediction refresh should use the newly uploaded datasetId.

3. PredictionRun must be saved in the same database as datasets and officialcases.

4. PredictionRun should use:
   - granularity: "monthly_district_cases"
   - datasetScope: uploaded datasetId or "all", depending on current design
   - basisDatasetId: uploaded datasetId
   - trigger: "official_upload"
   - status: "success" or equivalent

5. Determine the latest available official case month from the uploaded dataset.

Example:
If latest official case data is January 2026:
- basisYear = 2026
- basisMonth = 1
- forecastTargetYear = 2026
- forecastTargetMonth = 2

6. Save forecastTargetYear and forecastTargetMonth explicitly.

7. Group historical OfficialCase records by:
   - district or districtKey
   - year
   - month

8. Save district-level forecast payload in PredictionRun.

Expected payload shape:
{
  basisYear,
  basisMonth,
  forecastTargetYear,
  forecastTargetMonth,
  forecastHorizonMonths,
  districts: [
    {
      district,
      districtKey,
      historicalSeries: [
        { year, month, cases }
      ],
      forecast: [
        {
          year,
          month,
          predictedCases,
          lowerBound,
          upperBound,
          isPrimaryTarget
        }
      ],
      riskLevel,
      riskScore
    }
  ]
}

9. The first forecasted month should have:
   isPrimaryTarget: true

10. If prediction generation fails, do not break dataset upload. Instead:
   - keep dataset status validated
   - log the prediction error
   - optionally save errorMessage on the Dataset or ActivityLog

11. Add backend logs:
   - "Starting monthly district prediction refresh for datasetId..."
   - "PredictionRun saved..."
   - "Prediction refresh failed..."

Acceptance criteria:
- Uploading a valid raw XLSX creates OfficialCase records.
- After upload, predictionruns collection contains one new PredictionRun.
- The PredictionRun has basisYear, basisMonth, forecastTargetYear, and forecastTargetMonth.
- If latest data is January 2026, forecast target is February 2026.
- The PredictionRun is saved in foodsafemanila.predictionruns, not test.predictionruns.
- Dataset upload still succeeds even if prediction generation fails.
